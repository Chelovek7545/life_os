# Доступ агентов к Life OS

Первый этап: локальный MCP-сервер для задач. Он работает внутри запущенного
приложения и обращается к тем же API и SQLite, что и интерфейс. Изменения
появляются в обычных подписках приложения. Дополнительный процесс с прямым
доступом к базе не нужен.

В основной сборке AI-чат временно отключён по умолчанию. Это не отключает MCP:
сервер `agents.mcp` по-прежнему включается отдельно через `ENABLE_MCP=true`
и обязательный токен. Python, OpenVINO и локальная модель для MCP не нужны.

## Запуск на Windows

По умолчанию MCP выключен. В PowerShell из корня проекта:

```powershell
$env:LIFE_OS_MCP_TOKEN = [Guid]::NewGuid().ToString('N') + [Guid]::NewGuid().ToString('N')
C:\flutter\bin\flutter.bat run -d windows --dart-define=ENABLE_MCP=true
```

Токен доступен в переменной текущего процесса PowerShell; передай это же значение
клиенту через его защищённую настройку токена. Не записывай его в репозиторий.
Разрешены 32–256 печатных ASCII-символов без пробелов. Токен читается из окружения
приложения, поэтому новая сборка при его замене не нужна, достаточно перезапуска.
У готовой Windows-сборки сначала установи переменную, затем запусти exe из этого
же PowerShell. Флаг включения должен быть задан при её сборке.

Параметры подключения в MCP-клиенте:

| Параметр | Значение |
| --- | --- |
| Transport | Streamable HTTP |
| URL | http://127.0.0.1:48765/mcp |
| Header | Authorization: Bearer <значение LIFE_OS_MCP_TOKEN> |
| Protocol | 2025-06-18, согласуется при initialize |

Нужен клиент с поддержкой HTTP MCP и произвольного Authorization-заголовка.
Приложение должно оставаться открытым. Это локальный сервер для клиентов на том
же компьютере; удалённые подключения и публикация в сеть не предусмотрены.
Сервер слушает только IPv4 loopback и отклоняет запросы с Origin-заголовком:
прямое подключение из браузера не поддерживается. Первичная проверка выполнена
автоматическими HTTP-клиентами; настройка конкретного внешнего агента зависит
от его клиента. Веб-сборка не запускает сервер.

Если включить MCP без корректного токена или занять порт другим процессом,
запуск приложения завершится ошибкой и откатит старт модулей. Для обычного
запуска убери ENABLE_MCP=true; для доступа агента исправь токен или освободи
порт. Порт можно задавать через McpServerOptions в сборке зависимостей;
пользовательского переключателя порта и MCP в настройках пока нет.

## Доступные инструменты

| Имя | Аргументы | Результат |
| --- | --- | --- |
| tasks_list | query?, completed?, limit? (1–100), offset? | tasks, total, nextOffset |
| tasks_create | title, description?, dueDate?, startsAt?, endsAt? | task |
| tasks_complete | id | task или ошибка task_not_found |

Поиск учитывает название и описание без учёта регистра. По умолчанию возвращает
25 задач, включая выполненные; completed=false оставляет незавершённые.
Порядок стабильный по ID. nextOffset=null означает конец выдачи. Между страницами
список может измениться. Сейчас поиск получает задачи через существующий API
целиком и ограничивает выдачу в памяти; оптимизация SQL нужна лишь при измеренной
проблеме на больших списках.

Пример аргументов tasks_create:

```json
{
  "title": "Разобрать почту",
  "description": "Ответить на важные письма",
  "dueDate": "2026-11-10",
  "startsAt": "2026-11-10T10:00:00+03:00",
  "endsAt": "2026-11-10T10:30:00+03:00"
}
```

dueDate — только явно запрошенный дедлайн, календарная дата без часового пояса.
Для планирования «на завтра» используется startsAt. В startsAt можно передать
YYYY-MM-DD без времени (локальная полночь, в UI дата без часа). Время требует секунд и явного
смещения или Z; endsAt требует startsAt и должно быть позже. В ответах время
возвращается в UTC. Новая задача не привязана к проекту или родителю. Произвольное
редактирование, удаление, SQL, запуск программ и доступ к файлам не предоставлены.

tasks_complete изменяет только статус и updatedAt одной существующей задачи
в транзакции. Остальные поля, теги и ворклоги сохраняются. Повторное выполнение
уже завершённой задачи не меняет даже updatedAt; удалённая задача не создаётся.
Таймеры и ворклоги эта команда не запускает и не закрывает.

tasks_create создаёт новую задачу при каждом вызове. При потере ответа сначала
проверь данные через tasks_list: повтор без проверки может создать дубль.
Токен даёт доступ ко всем трём инструментам; разделения прав по клиентам и
подтверждения записи в интерфейсе пока нет.

## Протокол и жизненный цикл

Поддержан небольшой JSON-вариант Streamable HTTP без SSE-потока: initialize,
notifications/initialized, ping, tools/list, tools/call. После initialize клиент
передаёт выданный Mcp-Session-Id и MCP-Protocol-Version: 2025-06-18.
POST требует Content-Type: application/json и Accept: application/json,
text/event-stream. Уведомления получают 202, GET — 405, DELETE закрывает сессию.
Ответ инструмента содержит text и structuredContent; ошибки хранения
возвращаются без внутренних деталей. Некорректные аргументы дают JSON-RPC ошибку.

Ограничения: тело до 64 КиБ, ожидание очередной порции тела до 5 секунд,
до 16 активных обработчиков, до 32 сессий, удаление неактивной сессии через
30 минут при следующем запросе. После перезапуска клиент инициализируется заново.

PluginHost запускает agents.mcp после регистрации остальных модулей.
Остановка прекращает приём запросов, завершает принятые операции и освобождает
сервер до закрытия SQLite. Схема базы остаётся v10.

Основа реализации — официальный [транспорт MCP 2025-06-18](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports),
[жизненный цикл](https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle)
и [инструменты](https://modelcontextprotocol.io/specification/2025-06-18/server/tools).

## Следующие этапы

TaskAgentTools находится в чистом Dart-пакете agent_bridge и получает TasksApi
и TaskCompletionCommands через конструктор. Локальный помощник OpenVINO
вызывает тот же исполнитель напрямую без включения MCP.
Для новых возможностей сначала добавляй узкие команды и запросы существующего
модуля, затем явные инструменты с проверкой аргументов и тестами. Не открывай
контейнер, базу или весь репозиторий произвольному вызову модели.

Локальный текстовый помощник OpenVINO, выбор NPU/GPU/CPU, история диалога
и окно чата реализованы: [local-assistant.md](local-assistant.md). Голосовой ввод,
синтез речи и отдельное подтверждение каждой записи пока не реализованы.

## Проверка

```sh
flutter test test/features/agents test/app/mcp_composition_test.dart --no-pub
```

Тесты используют подставной API, настоящий HTTP на случайном loopback-порту
и SQLite в памяти. Пользовательские настройки, vault и база не затрагиваются.
