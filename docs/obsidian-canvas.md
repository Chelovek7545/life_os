Pulse/досок/заметок, инструкции пользователя и таблицы публичного API.
Этот документ подробно описывает файловую интеграцию и её историю.

## Где хранить файлы: vault или единая папка Pulse

В «Настройки → Граф» доступен выбор:

- **В vault Obsidian** — используются выбранный vault и отдельные пути четырёх
  категорий файлов, как раньше.
- **В папке Pulse на компьютере** — системным диалогом выбирается один корневой
  каталог (либо вводится абсолютный путь). Внутри него автоматически используются
  `Boards`, `Notes`, `Exports`, `Backups`; отдельных настроек подпапок в этом
  режиме нет. Интеграцию Obsidian включать не требуется. Выбранная папка и есть
  корень, дополнительная вложенная папка с именем Pulse не добавляется.

Режим и корень сохраняются в `graph_storage_target_v1`. По умолчанию сохраняется
прежний режим vault, чтобы обновление не меняло место хранения существующих данных.
Локальную папку при желании можно открыть как vault. Выбор места сохранения
не ограничивает список существующих заметок: подключённый Obsidian остаётся
доступен в Resources и при добавлении заметки на канвас, в том числе в локальном
режиме. В меню добавления на канвас доступны отдельные списки Notes и Obsidian,
в Resources они представлены отдельными панелями. Изменения отслеживаются
в обоих источниках.

При смене корня завершаются операции графов и библиотеки, открытые экземпляры
графа закрываются для новых команд. В выбранное место сохраняются только
основные `.canvas` с их раскладкой и связями; исходные доски не удаляются.
Существующие `.md` и вложения остаются по прежним путям, каталог заметок
не перепривязывается к копиям. Новые заметки графа создаются в выбранном каталоге
`notes` (в локальном режиме — `Notes`). Старые экспорты и резервные копии
не переносятся. Коллизия досок или изменение исходной доски во время сохранения
останавливает переключение без перезаписи исходных данных. Старые сессии
отзываются, даже если сам Obsidian-плагин продолжает работать.

Заметка внутри корня доски сохраняется стандартной карточкой `file` с относительным
путём. Для `.md` за пределами корня используется стандартная `text`-карточка:
текстовый снимок и `pulse.externalPath` с абсолютным путём оригинала. Pulse
восстанавливает связь при открытии, читает и редактирует исходный файл. Obsidian
показывает такой снимок как текст; правки этого снимка в Obsidian не записываются
в исходную заметку. Для обычного совместного редактирования `file`-карточек
выбирайте хранение досок в том же vault. Внешняя абсолютная привязка зависит
от расположения исходного файла на этом компьютере. Неподдерживаемые вложения
сохраняют тип и поля, пути перебазируются к оригиналам без копирования файлов;
отображение таких вложений за пределами vault в Obsidian не гарантируется.

Маршрутизацией владеет `graph.storage` (`GraphStorageRepository` в адаптере графа).
LifeGraph и Resources получают его через прежние контракты notes_api. Файловый
движок ObsidianVault переиспользуется как библиотека для локальной папки;
ObsidianPlugin в локальном режиме без интеграции не запускается. Все принятые
операции завершаются перед остановкой движка/закрытием базы. SQLite не переносится.

## Названия файлов и панели библиотеки

Markdown-карточка на канвасе показывает имя файла без `.md` в отдельной шапке
с иконкой документа. Заголовок вычисляется из исходного пути, не вставляется
в содержимое и виден при редактировании; длинное имя сокращается, полное доступно
в подсказке. После конвертации стикера в файл шапка появляется сразу.

В Resources рядом расположены панели **Obsidian Vault** и
**Markdown-заметки графа**; при доступной ширине менее 840 px панели идут
друг под другом. Первая показывает только подключённый vault, вторая — только `.md` внутри
настроенной папки Notes, включая её подпапки. Внешние файловые ссылки из
каталога сфер сюда не добавляются: заметка Obsidian не появляется в панели
Markdown только из-за добавления на канвас. Если Notes находится внутри vault,
файлы этой папки доступны также в общем дереве vault.

Обе панели открывают общий редактор исходного `.md`. Если ранее обнаруженный файл Notes
недоступен, можно прочитать сохранённый текст без возможности записи; причина
показана в диалоге. Ошибка vault не скрывает локальный список Markdown.
Стикеры без файловой привязки остаются отдельной сеткой под панелями.
Смена папки Markdown обновляет панель, не перемещая существующие заметки.

`NotesLibrarySourcesApi` в notes_api предоставляет два состояния источников
от GraphStorageRepository. ResourcesViewModel получает их через существующую
подписку VaultNotesApi: новых файловых watcher-ов или зависимости на реализацию
Obsidian в resources_plugin нет. В тестах/адаптерах без группировки источников
сохраняется прежнее представление VaultNotesApi как Obsidian.

## Переименование и добавление существующих Markdown-заметок

В режиме редактирования стикера нажатие на файловый заголовок превращает его
в однострочное поле прямо в шапке. Enter или уход фокуса сохраняет название,
Escape отменяет его правку. Во время записи показан индикатор, повторная отправка
блокируется; ошибка остаётся под полем вместе с введённым именем для исправления.
Отдельного окна переименования нет. Название меняет сам `.md` в прежней папке; текст заметки,
ID, размеры, положение и связи стикера сохраняются. Текущий черновик текста
коммитится до переименования. Пустое имя, путь вместо имени и недопустимые символы
отклоняются; `.md` не добавляется повторно, существующий файл не перезаписывается.
Совпадающие с точки зрения файловой системы пути считаются прежним именем
(в Windows это также смена только регистра).

`MarkdownNoteRenameApi` в notes_api предоставляет команду, разрешение прежнего
пути и поток NotePathChange. Файловый движок обновляет ссылки file/background и
pulse.externalPath в основных досках настроенной папки Boards. Маршрутизатор
обновляет доски обоих подключённых корней и каталог всех сфер; открытые модели
подписываются на смену пути. Запоздавшие записи разрешают старый путь в новый,
а сохранения каталога выполняются последовательно и нормализуют устаревшие ссылки.
CAS учитывает собственное изменение пути, сохраняя обнаружение посторонних правок.
Сессии, ID и пользовательские edges не пересоздаются. Остановка дожидается
принятого переименования и записей.

Исходный `.md` удаляется только после сохранения нового файла, обновления ссылок
и каталога и проверки, что исходный текст не изменился снаружи. При сбое на этом
этапе исходник и новая копия остаются; сообщение содержит путь копии. Резервные
снимки, экспорты, произвольные Canvas вне настроенных Boards и Markdown-ссылки
в других заметках не переписываются. Внешние переименования вне Pulse по-прежнему
не отслеживаются как перенос пути.

«Добавить заметку» теперь отдельно предлагает **«Из Markdown-хранилища»** и
**«Из Obsidian»**. Первый список берётся только из выбранной папки Notes и её
подпапок, второй — из подключённого vault. Выбор создаёт новую карточку со ссылкой
на исходный `.md`, без копирования файла. Локальный список работает при отключённом
Obsidian. Пункт создания нового `.md` сохранён.

## Сохранение копии заметки в любую папку

ПКМ по стикеру или Markdown-карточке → **«Сохранить копию .md в папку…»** открывает
системный выбор любой папки компьютера, затем диалог имени. Записывается текущий
текст заметки, включая предварительно коммитнутый черновик. Исходная карточка,
её ID, позиция, связи и привязка к файлу не меняются. Копия за пределами хранилища
не становится внешней `file`-ссылкой Canvas, что сохраняет переносимость доски.
Отмена выбора не создаёт файл; совпадение имени не перезаписывает существующий .md.
Копирование доступно даже без выбранного корня графа и без Obsidian.

Системный диалог реализован официальным Flutter [file_selector](https://pub.dev/packages/file_selector); в UI-тестах
выбор каталога подставляется, реальные диалоги на пользовательском компьютере
для проверки не открываются.

## Выбор папок и Markdown-заметки

В режиме vault в настройках модуля **«Граф»** можно выбрать папки отдельно для каждого вида
файлов. Кнопка папки показывает существующие каталоги; поле также принимает путь
новой папки. Пустое поле означает корень vault, пути сохраняются относительно
него с `/`. Абсолютные пути и выход через `..` отклоняются.

| Файлы | По умолчанию |
| --- | --- |
| Доски сфер | `Pulse/Boards` |
| Новые Markdown-заметки | `Pulse/Notes` |
| Экспорты | `Pulse/Canvases` |
| Новые резервные копии и конфликты | `Pulse/Backups` |

Настройки принадлежат LifeGraph и сохраняются одним объектом
`graph_storage_folders_v1` в SharedPreferences. Прежний `obsidian_folders_v1`
читается как fallback до первого сохранения новых настроек, пути не сбрасываются.
При смене папки досок текущие основные `.canvas` копируются в новое место.
Исходные файлы остаются архивными копиями, дальнейшие правки идут в новую папку;
открытые сессии переключаются после завершения копирования в очереди vault.
Если в целевой папке есть одноимённая доска с другим содержимым, настройка
не применяется и ни один из этих файлов не заменяется. Изменённый во время
копирования исходник также вызывает ошибку. Старые экспорты, резервные копии и
уже созданные Markdown-файлы не перемещаются: выбор этих папок влияет на новые
файлы. Существующие ссылки на заметки сохраняются.

На доске через «Добавить заметку» → **«Создать .md»** доступны название и текст
нового файла. Он создаётся в выбранной папке заметок и сразу добавляется как
карточка `file`. Правый клик на заметке открывает контекстное меню в палитре графа
с редактированием и удалением с доски; у стикера дополнительно доступно
**«Преобразовать в .md»**. На сенсорном экране меню открывается долгим нажатием.
Отдельной кнопки опций на карточке нет. Конвертация сохраняет текст в файл
и заменяет представление карточки.
Сохраняются ID стикера и карточки Canvas, координаты, размеры, порядок и edges.
Редактируемый черновик сначала коммитится; конвертация выполняется через очередь
графа с flush. Имя с `.md` не получает повторного расширения. Существующий файл
не перезаписывается: при совпадении имени стикер остаётся прежним.

Удаление файловой карточки не удаляет `.md`. Обратная конвертация в стикер пока
не добавлена. Если файл создан, а последующая запись доски не удалась, файл
сохраняется в vault для восстановления; автоматического удаления нет.

`GraphStorageSettings` находится в lifegraph_plugin; AppGraphStorageSettings
адаптирует SharedPreferences. LifeGraph регистрирует секцию «Граф», применяет
начальные пути без повторного копирования архивов и владеет подпиской на изменения.
Секция видна и при выключенной интеграции. ObsidianPlugin управляет только vault;
в нём нет настроек/подписок папок. Нейтральный `CanvasStorageFoldersApi` и DTO
`VaultFolders` в notes_api задают файловому адаптеру пути операций, а сам адаптер
продолжает выполнять копирование и запись. Настройки хранилища и UI ему не принадлежат.
Общая DefaultNoteCard сообщает позицию контекстного вызова через onContextMenu;
конкретные действия и палитра меню принадлежат UI графа. GraphView учитывает смену
источника заметки, даже когда текст и положение не меняются.

## Текущее состояние: основная доска сферы

В режиме Obsidian при выбранном vault открытый граф автоматически сохраняется
в **`<vault>/Pulse/Boards/<sphereId>.canvas`**. Редактировать в Obsidian следует
этот файл. Старые файлы в `Pulse/Canvases` остаются отдельными экспортами;
основной файл не выбирается из них автоматически. Пользователь подтвердил открытие
экспорта первого этапа в Obsidian; полный новый сценарий ещё требует проверки там.

Первое открытие без основного файла переносит прежнюю раскладку/стикеры из
SharedPreferences. Первая успешная запись создаёт независимую исходную копию
`<sphereId>.migration-<uuid>.canvas` в выбранной папке резервных копий.
Прежние версии создавали копию рядом с основной доской; такие файлы остаются
на месте. Старые позиции не изменяются;
заметки SharedPreferences далее обновляются как зеркало для Resources/офлайн.
Если не выбраны ни vault, ни локальный корень Pulse, остаётся прежний режим хранения.

Из Canvas читаются позиции и размеры бизнес-карточек, обычные текстовые карточки
и ссылки на целые Markdown-файлы. Отрицательные координаты поддерживаются через
сдвиг отображения и расширение рабочей области; при записи сдвиг убирается.
Координаты экспортируемых карточек округляются до пикселя. Пользовательские ID
бизнес-карточек сохраняются через `pulse.entityId`; при отсутствии метаданных
поддерживается исходный ID `pulse:<UUID>`. Повторные размещения одной сущности
пока отклоняются как неподдерживаемые, файл не перезаписывается.

Иерархия и содержимое бизнес-карточек генерируются из БД. Перемещение карточки
не меняет родителя; правки её текста/стрелок в Obsidian не меняют задачи и проекты.
Группы, сайты, вложения, ссылки на заголовки, неизвестные поля и пользовательские
edges сохраняются при записи, но пока не отрисовываются в Pulse.
Удаление заметки в Pulse убирает её карточку и связанные с ней edges, не `.md`.

Изменения файла подхватываются при открытии графа. Кнопка «Перечитать Canvas»
убрана. Непрерывного файлового live-sync пока нет. Перед записью
сравнивается полное содержимое с прочитанной версией. При конфликте основной файл
остаётся внешним, локальный снимок пишется в `<sphereId>.conflict-<uuid>.canvas`
в выбранной папке резервных копий, статус
становится failed. Только при ошибке сохранения контекстное меню заметки предлагает
«Загрузить внешнюю версию» с подтверждением, чтобы восстановиться после конфликта.
Содержимое связанных заметок включается в `pulse.cachedText` для офлайн
и восстановления. Это оптимистическая проверка, не межпроцессная блокировка:
одновременного редактирования непосредственно в момент замены файла лучше избегать.
Повреждённый файл не заменяется пустым документом. Смена vault отзывает старую сессию.

Доска сохраняется одним DebouncedWriter. Переключение сферы и остановка завершают
принятые записи под исходным ID/сессией. Markdown-файлы и зеркало обновляются
после записи доски; сбой этой части оставляет операцию несохранённой для повтора.

## Первый этап: экспорт сферы

На экране графа кнопка «Экспорт в Obsidian Canvas» рядом со статусом сохранения
создаёт файл `<vault>/Pulse/Canvases/<sphereId>-<exportUuid>.canvas`.
Нужны включённый плагин Obsidian и выбранный vault. Полный путь показывается
после экспорта. Каждый экспорт — новый снимок: прежние файлы, в том числе
изменённые в Obsidian, не перезаписываются.

Перед экспортом завершаются отложенные записи. Документ содержит сферу,
потомков из проекции БД (включая свёрнутые ветви), фактические координаты
с учётом автоматической раскладки, размеры, цвета, иерархию и заметки.
На момент первого этапа SQLite и SharedPreferences оставались основными
хранилищами; последующие изменения описаны выше.

## Формат

Основа — [JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/).
Поле `type` стандартное, значения `pulse-task` и подобные не используются.

| Элемент Pulse | Представление |
| --- | --- |
| Сфера, цель, проект, задача | `text`, Markdown-снимок названия/описания/статуса; `pulse.kind` и `pulse.entityId` связывают карточку с БД |
| Стикер | `text`, текст внутри Canvas |
| Заметка vault | `file`, путь от корня vault с разделителем `/`, без копирования Markdown |
| Иерархия | `edges`, `pulse.kind: hierarchy`, детерминированный ID из пары родитель/ребёнок |

ID карточек сейчас `pulse:<entityId>` и `note:<noteId>` — отдельные пространства.
Повторное размещение одной сущности в будущем потребует отдельных ID карточек
при неизменном `pulse.entityId`. Корневое поле `pulse` содержит `version: 1`
и `sphereId`. Дополнительные поля Pulse не являются частью стандарта.

Координаты и размеры округляются до целых пикселей. Повторные ID, бесконечные/
нечисловые координаты, неположительные размеры отвергаются. Заметка за пределами
выбранного vault или из неподдерживаемого источника вызывает явную ошибку.
Стиль и интерактивные контролы Pulse не переносятся в Obsidian.

## Границы и жизненный цикл

- `lifegraph_plugin/canvas_document.dart` строит JSON через `GraphNodeData`
  и `CanvasNote`, без Flutter и файловой системы.
- `LifeGraphViewModel.exportCanvas` использует очередь операций графа и flush;
  принятый экспорт завершается при dispose, новые операции после остановки запрещены.
- Дополнительный контракт `VaultCanvasApi` находится в `notes_api`.
  `ObsidianVault` реализует файловую запись без знания бизнес-модулей/Drift.
  Запись идёт через временный файл в той же папке, завершается до остановки;
  смена vault отклоняет ещё не начатый экспорт.
- Кнопка принадлежит экрану графа, MainScreen не меняется.
