## Назначение и состав

LifeGraph показывает сферу жизни и связанные с ней сущности в виде доски:
карточки сферы, целей, проектов, задач и заметок. Бизнес-модули определяют свои
виды карточек, формы и разрешённые действия. Граф объединяет их, хранит раскладку
и выполняет команды через общие контракты.

| Часть | Ответственность |
| --- | --- |
| `lifegraph_plugin` | Проекция графа, модели Pulse/открытых досок, команды, раскладка, заметки и сохранение Canvas |
| `graph_canvas` | Отображение, камера, выделение, жесты, сворачивание, редактирование стикеров |
| `graph_api`, `graph_ui`, `graph_components` | Контракты данных/команд, реестры карточек и редакторов, общие формы и оформление |
| `graph.storage` | Адаптер приложения, выбирающий файловый корень и обновляющий ссылки |
| `obsidian_plugin` | Подключение vault и файловый движок; движок переиспользуется для локальной папки без запуска интеграции |
| `resources_plugin` | Модель библиотеки заметок и операции через `notes_api` |

Настройки расположения файлов принадлежат секции **«Граф»**. Секция Obsidian
отвечает за подключение vault. Это встроенные модули приложения; загрузки
стороннего исполняемого кода во время работы нет.

## Быстрый старт

1. Откройте Pulse и создайте сферу либо выберите существующую.
2. В «Настройки → Граф» выберите vault Obsidian или локальную папку Pulse.
3. На доске создавайте/привязывайте бизнес-карточки через их формы.
4. Нажмите кнопку добавления заметки и выберите стикер, существующий `.md`
   из Notes/Obsidian либо создание нового `.md`.
5. Для правки заметки дважды нажмите на её текст или используйте ПКМ →
   «Редактировать». У файловой заметки нажмите название в шапке, чтобы менять его
   прямо на карточке: Enter/уход фокуса сохраняет, Escape отменяет.

Если файловый корень не выбран, прежние локальные стикеры и раскладка продолжают
работать через настройки приложения. Для создания нового `.md` и экспорта Canvas
нужен файловый корень. Отдельную Markdown-копию можно сохранить в выбранную папку
и без такого корня.

## Экран Pulse

- **Сферы:** создание сферы по названию, список существующих сфер, открытие
  отдельной доски, счётчик узлов.
- **Иерархия и цели:** обзор данных из API сфер, целей, проектов и задач.
- **Статистика:** текущая задача с интервалом `startsAt..endsAt`, задачи текущего
  дня, быстрый переход к редактору задачи и переключение её выполнения.
  Для текущей задачи приоритет имеет статус in-progress.
- **Диаграмма за 7 дней:** число задач со статусом done, распределённых по
  `startsAt`, а при его отсутствии — по `updatedAt`; среднее за семь дней.
  Это не журнал фактических моментов завершения задач.
- **Подключаемые панели:** модули добавляют содержимое через слоты `pulse.center`,
  `pulse.toolbar`, `pulse.overlay`. Например, панель привычек принадлежит модулю
  привычек, а не файловому движку Canvas.
- **Адаптация экрана:** при достаточной ширине панели разделены, на узком экране
  используется вертикальная компоновка. Редактор задачи открывается через общий
  механизм приложения с сохранением текущей вкладки Pulse.

## Управление доской

| Действие | Результат |
| --- | --- |
| Открыть сферу | Загружает проекцию сущностей из БД, раскладку и заметки доски |
| Перемещать фон, менять масштаб | Меняет положение камеры; доступны Zoom in/out и Fit graph |
| Выделить карточку | Делает её текущей для действий и визуально выделяет |
| Перетащить карточку | Меняет координаты; сохранение запускается после окончания жеста |
| Свернуть ветвь | Временно скрывает потомков, сохраняя данные и их позиции |
| Создать потомка | Выполняет команду соответствующего бизнес-модуля и размещает новую карточку |
| Привязать существующую сущность | Добавляет её через зарегистрированную команду модуля |
| Редактировать сущность | Открывает форму, зарегистрированную её модулем |
| Удалить сущность | Использует команду удаления с сохранением детей либо удалением поддерева; это изменение бизнес-данных |
| Выйти с доски | Завершает принятые записи перед закрытием |

Перемещение карточки не меняет её родителя. Сворачивание и камера относятся
к представлению и не удаляют скрытых потомков. При экспорте учитывается полная
проекция, включая свёрнутые ветви. Координаты и размеры поддерживают внешнюю
раскладку Canvas, в том числе отрицательные координаты через сдвиг отображения.

## Все действия с заметками

| Действие | Где доступно | Что происходит |
| --- | --- | --- |
| Пустой стикер | Добавление заметки | Текст хранится внутри Canvas; отдельный `.md` не создаётся |
| Создать `.md` | Добавление заметки | Создаёт файл в выбранной папке Notes и связанную карточку |
| Из Markdown-хранилища | Добавление заметки | Показывает `.md` папки Notes и подпапок; добавляет ссылку на исходник |
| Из Obsidian | Добавление заметки | Показывает подключённый vault; добавляет ссылку без переноса файла |
| Редактировать текст | Двойное нажатие или ПКМ | Текст правится на стикере; у `.md` сохраняется в исходном файле |
| Изменить название `.md` | Нажатие заголовка при редактировании | Ввод прямо в шапке, затем переименование файла в прежней папке |
| Переместить/изменить размер | Перетаскивание/ручка стикера | Сохраняет геометрию карточки |
| Преобразовать в `.md` | ПКМ по обычному стикеру | Создаёт файл из текста, сохраняя ID, координаты, размеры и edges |
| Сохранить копию `.md` в папку | ПКМ по заметке | Записывает текущий текст в любую выбранную папку; исходная привязка не меняется |
| Удалить с доски | ПКМ или удаление карточки | Удаляет карточку и её связи, оставляя сам `.md` на диске |
| Загрузить внешнюю версию | ПКМ после ошибки сохранения | После подтверждения перечитывает внешний Canvas; локальная конфликтная копия остаётся |

Текст Markdown отображается и редактируется как текст. Название файловой заметки
показано отдельно от содержимого; изменение заголовка не вставляет его в текст.
Длинное название сокращается в обычном состоянии, полное доступно в подсказке.
ПКМ и долгое нажатие открывают меню в палитре графа. Отдельной кнопки опций нет.

### Название прямо на стикере

1. Перейдите к редактированию текста заметки.
2. Нажмите на файловый заголовок: он станет однострочным полем с выделенным именем.
3. Enter или нажатие снаружи сохраняет имя; Escape отменяет только правку имени.
   Текст заметки, введённый до перехода в заголовок, коммитится отдельно.
4. На время записи поле блокируется и показывает индикатор. Ошибка отображается
   под полем; введённое имя остаётся, его можно исправить и отправить повторно.

Пустое имя, путь вместо имени и недопустимые символы отклоняются. Расширение `.md`
не дублируется, существующий файл не перезаписывается. ID, геометрия и связи
карточки сохраняются. Обновляются ссылки основных досок в обоих текущих корнях,
каталог сфер и открытые графы. Запоздавшие записи по старому пути направляются
в новый файл. Если переименование не завершилось, исходник и созданная копия
остаются; сообщение указывает путь копии.

## Расположение файлов

| Назначение | Vault по умолчанию | Локальная папка Pulse |
| --- | --- | --- |
| Основные доски | `Pulse/Boards/<sphereId>.canvas` | `Boards/<sphereId>.canvas` |
| Новые `.md` графа | `Pulse/Notes` | `Notes` |
| Отдельные экспорты | `Pulse/Canvases/<sphereId>-<uuid>.canvas` | `Exports/<sphereId>-<uuid>.canvas` |
| Новые резервные/конфликтные снимки | `Pulse/Backups` | `Backups` |

В режиме vault четыре каталога выбираются отдельно относительно его корня.
Пустой путь означает корень vault; абсолютный путь и `..` в этих полях запрещены.
В локальном режиме один раз выбирается общий корень, подпапки фиксированы.
Выбранная папка сама является корнем: дополнительная вложенная Pulse не создаётся.

При смене корня сначала завершаются операции графов и библиотеки, старые модели
и сессии закрываются. В новое место сохраняются основные доски, сохраняя оригиналы.
Существующие `.md` и вложения остаются на месте; новое назначение используется
для новых заметок. При коллизии другой файл не заменяется. Старые экспорты и
резервные копии автоматически не переносятся. SQLite не перемещается.

При смене только папки Boards в vault копируются основные доски и переключаются
открытые сессии. При запуске сохранённые папки применяются без повторного копирования
архивов. Режим хранится в `graph_storage_target_v1`, папки — в
`graph_storage_folders_v1`; старый `obsidian_folders_v1` читается как fallback.

Локальное хранение работает с `ENABLE_OBSIDIAN=false`. В этом случае графовые
настройки и Notes доступны, а подключённого vault в библиотеке нет.

## Хранилище заметок

В Resources две панели: **Obsidian Vault** и **Markdown-заметки графа**.
От ширины 840 px они стоят рядом, ниже — друг под другом.

- Панель Obsidian показывает дерево подключённого vault.
- Панель Markdown показывает только файлы текущей Notes и её подпапок,
  включая файлы, которые ещё не добавлены на доску. Внешние ссылки каталога
  сфер сюда не добавляются. Если Notes находится внутри vault, её файлы
  доступны и в общем дереве этого vault.
- Оба списка открывают общий редактор исходного `.md`. Недоступный файл,
  ранее обнаруженный источником, можно прочитать из сохранённого текста без записи.
- Ошибка Obsidian не скрывает локальные Markdown-заметки. Кнопка обновления
  перечитывает источники. Стикеры без файловой привязки показаны отдельной сеткой.

## Сохранение и восстановление

**Источники данных:** бизнес-сущности и их иерархия принадлежат SQLite/API модулей;
геометрия и заметки — основной доске Canvas; текст файловых заметок — `.md`.
SharedPreferences сохраняет прежние позиции и зеркало/каталог заметок для офлайн-данных.

Для доски используется один DebouncedWriter. Статусы: `draft`, `saving`, `saved`,
`failed`. Перед экспортом, переключением и остановкой завершаются принятые записи.
Новый экземпляр графа получает собственное состояние и подписки.

При первом переносе сохраняется `<sphereId>.migration-<uuid>.canvas`.
Это резервная копия начальной раскладки, не вторая активная доска.
Перед заменой основного файла сравнивается его полное содержимое с прочитанным.
При внешних изменениях исходный Canvas остаётся, локальная версия записывается
как `<sphereId>.conflict-<uuid>.canvas`, статус становится `failed`.
Для восстановления используйте контекстное меню заметки. Повреждённый, чужой
или неподдерживаемый документ не заменяется пустой доской.

Конфликтная проверка является оптимистической, межпроцессной блокировки нет.
Самостоятельные изменения Canvas читаются при открытии/восстановлении, а не
постоянно во время работы. Списки `.md` отслеживаются файловым движком отдельно.

## Совместимость с Obsidian

Используется JSON Canvas 1.0 с обычными типами `text` и `file`, а не `pulse-task`.
Метаданные Pulse находятся в дополнительных полях:

| Данные | Представление |
| --- | --- |
| Бизнес-карточка | `text`, `pulse.kind`, `pulse.entityId` |
| Обычный стикер | `text`, `pulse.noteId` |
| `.md` внутри корня | `file` с относительным путём, `pulse.cachedText` |
| `.md` вне корня | `text` со снимком и `pulse.externalPath` |
| Иерархия | `edges`, `pulse.kind: hierarchy` |
| Документ | `pulse.version: 1`, `pulse.sphereId` |

Внешний файл за пределами корня остаётся живой связью в Pulse, но Obsidian
показывает текстовый снимок. Для обычных file-карточек совместного vault храните
доску и заметки внутри одного vault. Изменения текста бизнес-карточек и стрелок
в Obsidian не импортируются в БД.

Неизвестные поля, группы, ссылки, вложения и пользовательские edges сохраняются
при записи, даже если Pulse пока не умеет их отображать. Экспорт создаёт новый
самостоятельный снимок и не заменяет основной Canvas. Координаты и размеры
при записи округляются до пикселя.

## Архитектура и публичные функции

### Точки входа

- `lifegraph_plugin/lifegraph_logic.dart` — чистая логика: GraphBuilder и GraphNode.
- `lifegraph_plugin/lifegraph_plugin.dart` — также модуль и модели интерфейса.
- `lifegraph_plugin/canvas_document.dart` — `createSphereCanvas`, CanvasEntity.
- `lifegraph_plugin/canvas_board.dart` — чтение, проверка и слияние CanvasBoardDocument.
- `lifegraph_plugin/canvas_note_mapper.dart` — преобразования записей и стикеров.
- `lifegraph_plugin/graph_storage_settings.dart` — режим/папки и контракт настроек.

| API | Назначение |
| --- | --- |
| `LifeGraphPlugin` | Регистрация экрана `pulse`, настроек «Граф», владение ресурсами |
| `GraphBuilder.watchGraph` | Объединение вкладов, проверка ID/корня, проекция достижимых потомков и наследование цветов |
| `PulseScreenViewModel.initialize` | Подписки на сферы, цели, проекты и задачи |

| `LifeGraphViewModel.switchSphere` | Завершение предыдущих записей и открытие нового контекста |
| `createChild`, `attachNode`, `updateNode`/`updateGraphNode`, `deleteNode` | Бизнес-команды через реестр модулей |
| `actionsFor`, `nodeById` | Контекст действий с защитой от устаревшего графа и поиск узла |
| `moveNode`/`commitMove` | Живое перемещение и сохранение координат |
| `createNote`, `createNoteWithText`, `createMarkdownNote` | Создание стикера, ссылки или нового файла |
| `updateNoteText`, `renameNote`, `convertNoteToMarkdown` | Текст, имя файла и преобразование стикера |
| `moveNote`/`commitNoteMove`, `resizeNote`/`commitNoteResize` | Геометрия заметок |
| `removeNote`, `refreshNotes` | Удаление карточки без файла, повторное чтение текста |

| `reloadCanvasBoard` | Загрузка внешнего варианта после ошибки |
| `graphStream`, `notesStream`, `spheresStream`, `saveStatus` | Реактивное состояние доски |
| `hasCanvasBoard`, `canvasBoardPath`, `canvasWorldSize`, `currentSphereId` | Текущий файловый контекст и геометрия мира |
| `vaultNotes`, `markdownLibraryNotes`, `obsidianLibraryNotes` | Общий каталог и раздельные источники выбора |
| `canCreateMarkdown`, `canSaveMarkdownCopy`, `canExportCanvas`, `canRenameNote` | Доступность файловых действий |
| `flush`, `stopAccepting`, `isClosing`, `dispose` | Завершение принятых операций и отзыв новых |

### Контракты хранения и расширения

| Контракт/реестр | Возможности |
| --- | --- |
| `GraphContributorRegistry` | Подключение данных новых видов узлов |
| `GraphCommandRegistry` | Создание, обновление, привязка, удаление через владельца сущности |
| Реестры `graph_ui` | Карточки, размеры, формы и действия без условий в оболочке |
| `GraphPositionsStore`, `CanvasNotesStore`, `NotesCatalog` | Позиции, заметки и библиотека через абстракции |
| `VaultNotesApi` | Состояние, обновление, чтение/запись и создание Markdown |
| `NotesLibrarySourcesApi` | Раздельные состояния Notes и Obsidian |
| `VaultCanvasApi`, `VaultCanvasBoardsApi`, `CanvasBoardSession` | Экспорт, открытие и CAS-запись основной доски |
| `CanvasStorageFoldersApi` | Настройка и перечисление папок |
| `MarkdownNoteSaveApi` | Отдельная копия текста в выбранный каталог |
| `MarkdownNoteRenameApi`, `NotePathChange` | Переименование, смена пути и разрешение старых ссылок |
| `GraphStorageSettings` | Чтение папок и подписка на изменения |

Связи собираются в `lib/app/dependency_container.dart` и адаптерах `lib/app/plugins`.
`lifegraph.screen` зависит от бизнес-модулей и `graph.storage`; файловый адаптер
при подключённой интеграции зависит от `obsidian`. Потребители останавливаются
раньше источников. Подписки, модели, очереди, фокусы и контроллеры принадлежат
создавшим их модулям/виджетам. Старые формы и callbacks не должны менять новый
экземпляр после переключения/перезапуска.

## Ограничения

- Непрерывного live-sync основной `.canvas` и импорта бизнес-правок из Obsidian нет.
- Пользовательские edges сохраняются, но создание/отрисовка произвольных связей
  в Pulse пока не реализованы.
- Группы, веб-ссылки, изображения и file-ссылки на разделы заметок сохраняются,
  но не являются полноценно отображаемыми карточками Pulse.
- Повторное размещение одной бизнес-сущности отклоняется; несколько стикеров
  одного `.md` допустимы и ссылаются на один файл.
- Обратной конвертации `.md → text` нет. Удаление стикера не удаляет файл.
- Внешние переименования/перемещения вне Pulse не перепривязывают ссылки автоматически.
- Переименование из Pulse не меняет Markdown-backlinks, произвольные Canvas вне
  настроенных Boards, старые экспорты и резервные снимки.
- Совпадающие пути считаются прежним именем; на Windows сюда относится смена
  только регистра. Абсолютные внешние привязки зависят от расположения файлов
  на конкретном компьютере.
- Нельзя гарантировать отображение файлов/вложений вне корня в самом Obsidian.
- Файловые функции требуют доступной папки и соответствующих прав ОС; веб-работа
  с произвольными папками компьютера здесь не заявляется.

## Проверка

Тесты используют БД в памяти, временные каталоги и подставные выборщики папок.
Они не открывают реальные диалоги и не изменяют пользовательские vault/базу.

```sh
flutter test --no-pub test/features/lifegraph test/features/resources test/app/local_graph_storage_test.dart
flutter test --no-pub test/architecture test/core/plugins test/core/storage test/app
flutter analyze --no-pub
```

Особенно важны `canvas_board_persistence_test`, `markdown_note_card_test`,
`markdown_note_rename_test`, `graph_storage_repository_test` и
`local_graph_storage_test`. История полных прогонов и ограничения окружения
зафиксированы в [obsidian-canvas.md](obsidian-canvas.md) и [AGENTS.md](../AGENTS.md).
