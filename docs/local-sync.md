## Включение

Модуль `sync.local` включается сборочным параметром; в исходном коде он
по умолчанию выключен. Регистрация идёт через plugin_ui, без условий MainScreen.

```sh
flutter run --dart-define=ENABLE_SYNC=true
flutter build apk --release --dart-define=ENABLE_SYNC=true
flutter build windows --release --dart-define=ENABLE_SYNC=true
```

Готовый APK находится в `build/app/outputs/flutter-apk/app-release.apk`.
Готовая Windows-сборка: `build/windows/x64/runner/Release/Pulse.exe`.
Рядом с Pulse.exe должны оставаться её DLL и каталог data.

Для обмена флаг `ENABLE_SYNC=true` нужен на обоих устройствах. Его можно
совмещать с другими [флагами сборки](../README.md#build-an-android-apk-with-optional-modules).

Включение модуля регистрирует секцию «Локальная синхронизация» в настройках
и подготавливает защищённые ключи. Учёт БД и первый запуск сетевого приёма
требуют действий пользователя. Приложение запоминает выбор приёма и
восстанавливает его при запуске. Web не регистрирует модуль;
sync_native.dart использует заглушку без dart:io.

## Подключение двух устройств

Кнопка синхронизации находится справа в верхней панели экрана Pulse. В окне
выберите устройство и нажмите «Синхронизировать». Шкала показывает подтверждённые
записи журнала в обоих направлениях и сохранение Markdown и Canvas. Карточки
показывают статус заметок, задач с их журналами и тегами, проектов, графов
со сферами и целями, привычек с отметками. Этапы и прогресс видны на обоих
устройствах. Если окно синхронизации закрыто, после успешного обмена Pulse
показывает встроенное уведомление. Для зеркального прогресса нужны обновлённые сборки
на обоих устройствах.
Нажмите «Настройки», чтобы создать пространство, или «Конфликты» для сравнения версий прямо в окне синхронизации.
Если связь прервалась, проверьте, включён ли приём на втором устройстве, и
повторите обмен. Тест TLS проверяет передачу сохранённой офлайн-задачи после
возвращения второго устройства и отсутствие дубликатов при повторном обмене.

1. На устройстве с исходными данными создайте пространство в настройках.
   Bootstrap сохраняет прежние ID и даты, создаёт журнал и UUID тегов
   одной транзакцией. При нарушенных связях он откатывается.
2. Откройте окно синхронизации на двух устройствах в одной локальной сети.
   Включите приём на устройстве с исходными данными. Оно появится на радаре
   второго устройства. Нажмите на его имя и сверьте код на обоих экранах.
   Подтвердите совпадение сначала на принимающем запрос устройстве, затем на
   устройстве, отправившем запрос.
3. Если устройство не появилось, нажмите «Показать QR» на исходном устройстве.
   На Android нажмите «Сканировать QR», на Windows выберите «Открыть QR с
   изображения». Подтвердите запрос на исходном устройстве. QR одноразовый
   и действует пять минут. Текст приглашения доступен в настройках.
4. Пара появляется после завершения подтверждений. Для присоединения нужна
   пустая база или уже подключённое то же пространство. Проверка после
   подтверждения защищает записи, созданные за время ожидания.
5. Нажмите «Синхронизировать». Для пары из старой версии, если требуется,
   сначала нажмите «Проверить сопряжение» в настройках.

Данные передаются по HTTPS на TCP 48766. Обнаружение использует UDP 48767
и работает только при открытом окне синхронизации. Устройство отвечает на
запросы обнаружения при включённом приёме и настроенном пространстве.
Радар показывает только полученные ответы. При изоляции устройств или
блокировке UDP используйте QR, если устройства доступны друг другу по HTTPS.
Модуль работает только с локальными
IP-адресами. HTTP, публичные IP и произвольные DNS-имена отклоняются. Параметры
сервера и хранилище ключей инъецируются для тестов; порты тестов случайные,
адреса — loopback. Фонового сервиса пока нет.

Переключатель «Приём по локальной сети» находится в окне синхронизации Pulse.
По нажатию на IP в той же карточке можно выбрать другой адрес. Выключение
приёма закрывает входящий listener. Явный
исходящий обмен с доступным подключённым устройством остаётся возможным.
После перезапуска ранее включённый приём восстанавливается по доступному IP.
Ключи и список устройств сохраняются. Изменения БД продолжают журналироваться
без открытого listener.

## Повторное подключение и отзыв

«Отозвать доступ» удаляет ключ пары на текущем устройстве. Следующие запросы
партнёра отклоняются; ранее принятая транзакция завершается. Полученные данные
не удаляются удалённо.

После смены адреса или отзыва можно создать новое приглашение и использовать
«Подключить приглашение в этом пространстве» на втором устройстве. Повторное
сопряжение требует подтверждения; для уже известного peer сначала отзывается
прежний доступ на принимающем устройстве. Существующая база допускается только
в том же datasetId, с сохранением deviceId и всех данных. Присоединиться таким
способом к другому пространству нельзя.

## Конфликты и ожидающие записи

Счётчики не называют данные полностью синхронизированными при наличии
конфликтов или pending. Кнопка «Конфликты» в окне синхронизации показывает
различающиеся поля и их значения по устройствам, а также доступные названия
связанных сущностей. Для Markdown подсвечиваются изменённые строки. Для Canvas
сравниваются карточки, их расположение и связи. «Только различия» сворачивает
совпадающие поля обычных записей. Нажмите на карточку устройства, чтобы выбрать
его версию, затем нажмите «Подтвердить версию». «Объединить вручную» позволяет
выбрать значения из разных версий.
При добавлении или удалении карточки Canvas выбирается её состояние целиком.
Сохранение создаёт новую ревизию с проверкой показанного набора вершин. Если версии уже изменились,
обновите список конфликтов.

При delete против edit сохраняются оба варианта, а в бизнес-таблицах действует
удаление. Можно подтвердить удаление; восстановление под старым ID запрещено.
Создание отдельной восстановленной копии этим экраном пока не реализовано.

### Привычки и Markdown

При обновлении уже сопряжённые устройства добавляют существующие привычки и
отметки в журнал. Ключ отметки состоит из ID привычки и календарного дня.
Одновременные правки одного дня сохраняются как конфликт одной отметки.

Настройте папку Pulse или vault с отдельной папкой Notes на каждом устройстве.
Обмен захватывает UTF-8-файлы .md внутри активной Notes, включая подпапки.
Вложения и остальные папки vault хранятся отдельно. Путь заметки относительный,
без учёта регистра. Переименование передаётся как появление новой заметки и
удаление старой. Предельный размер JSON-представления заметки — 1 МиБ.
Если папка не выбрана, полученные заметки остаются в журнале и сохраняются
в файлы при следующем обмене после выбора папки.

При конфликте Markdown каждая сторона сохраняет свой файл и показывает обе
версии в настройках. Можно раскрыть текст и выбрать версию или удаление.
Повторный обмен применяет решение к другой стороне. Изменения других программ
в этой папке захватываются при следующем ручном обмене.

### Доски Canvas

Нативный Pulse хранит независимые доски в `Boards/<canvasId>.canvas`. Если vault
или папка не выбраны, используется собственный каталог Pulse. Прежние файлы
сфер сохраняют старые ID. Из прежних сохранённых позиций и заметок без файла
создаётся доска при обновлении.

Доски передаются целиком по ID канваса, включая положения и размеры узлов,
текстовые стикеры, группы, карточки и связи. Карточки Markdown из Notes
привязываются к локальному пути принимающего устройства. Удаление карточки
сохраняет её Markdown-файл. Ссылки на внешние локальные файлы отображаются
на другом устройстве как карточки «Локальный файл».

Перед заменой Pulse проверяет исходный файл и сохраняет его копию в папке
Backups. При параллельных правках или при первом обмене двух разных досок
обе версии сохраняются. Устройства показывают одну и ту же версию временно,
пока пользователь не выберет доску в разделе «Конфликты». Открытый граф
перечитывается после записи файла.

Синхронизация обрабатывает доски в Boards размером до 1 МиБ в
формате обмена. Экспортированные снимки, резервные копии и вложения остаются
в локальном хранилище.

«Просмотреть ожидающие изменения» позволяет явно:

- переименовать конфликтующий тег;
- снять выбранную связь задачи/проекта/цели или теги задачи;
- перенести сохранённый WorkLog в существующую живую задачу.

Все исправления сохраняют историю и проверяют исходную основу. Неполные группы,
неизвестные причинные родители и ещё не полученные данные нельзя обойти
исправлением формы: сначала требуется повторный обмен. Программа не обнуляет
ссылки и не объединяет одноимённые теги автоматически.

## Ключи и протокол

Используется TLS 1.2+ сервера с закреплённым SHA-256 отпечатком сертификата.
Для каждой пары генерируется отдельный случайный 256-битный bearer-ключ;
это аутентификация пары поверх TLS, не mutual TLS с клиентскими сертификатами.
Сертификат создаёт [basic_utils](https://pub.dev/packages/basic_utils), TLS
выполняет dart:io. Собственных шифров и протоколов подписи нет.

Закрытый ключ и ключи пар хранятся одной версионированной записью через
[flutter_secure_storage](https://pub.dev/packages/flutter_secure_storage).
SQLite и SharedPreferences не содержат эти секреты. На Android resetOnError
выключен: сбой защищённого хранилища оставляет модуль офлайн, без автоматического
сброса ключей или plaintext fallback. Основное приложение продолжает работать,
повторное действие может заново открыть хранилище.

Приглашение содержит адрес, отпечаток, dataset/device ID, случайный одноразовый
секрет и срок. Секрет передаётся только после проверки закреплённого сертификата;
клиент использует SecurityContext без системных корней и запрещает redirects.
Host подтверждает отдельный nonce запроса, поэтому старое подтверждение не
может одобрить новый запрос того же устройства после restart.

Эндпоинты `/v1/pair`, `/v1/pair/confirm`, `/v1/hello`, `/v1/cursor`,
`/v1/plan`, `/v1/pull`, `/v1/push`, `/v1/progress`, `/v1/abort` и `/v1/finish` принимают
ограниченные JSON-сообщения. Push связывает источник batch с авторизованным peer;
dataset и версия протокола проверяются до доступа к данным. Ack следует за
коммитом существующего SyncStore. Повторы и неполные группы сохраняют прежнюю
идемпотентность. Ретрансляция допустима только внутри доверенной личной группы;
revision.deviceId — метаданные автора, не криптографическая подпись.

Обновлённые устройства связывают кадры прогресса с авторизованным устройством и
идентификатором сеанса. Подтверждённые пачки увеличивают счётчики на обеих
сторонах. Завершение фиксируется после применения файлов, а прерванный сеанс
закрывается явно или по тайм-ауту.

По умолчанию: до восьми принятых операций, до 6 MiB на HTTP-сообщение,
15 секунд на обычный запрос, до 100 ревизий в пачке с прежним лимитом 4 MiB.
Остановка отзывает поколение, закрывает клиентские соединения/listener,
завершает подготовку ключей и уже принятые операции БД до закрытия AppDatabase.
Сбой одной очистки не отменяет остальные; ошибки возвращаются владельцу.

## Проверки и оставшаяся работа

### Полевой сценарий Windows ↔ Android

Для обоих устройств используйте [сборки с локальной синхронизацией](#включение).
Установите APK поверх текущей версии, чтобы сохранить данные приложения.
Если база телефона уже заполнена независимо, первый тест присоединения
останавливается: объединения двух независимых пространств пока нет.

После сопряжения выполните по порядку:

1. Создайте на Windows задачу «SYNC-PC», запустите обмен и проверьте её появление
   на телефоне. Измените название на телефоне и запустите обмен обратно.
2. Завершите задачу на телефоне. После обмена статус на Windows должен совпасть.
3. Отключите сеть телефона, создайте «SYNC-OFFLINE» и измените существующую
   задачу. После возврата сети и ручного обмена изменения должны появиться
   на Windows без дубликатов.
4. До очередного обмена задайте одной задаче разные названия на двух устройствах.
   После обмена должен появиться конфликт. Выберите вариант в настройках,
   повторите обмен и проверьте одинаковое название и отсутствие конфликта.
5. Удалите тестовую задачу, повторите обмен дважды. На другом устройстве она
   должна исчезнуть и не восстановиться после второго обмена.
6. Перезапустите оба приложения. Устройства должны остаться в списке; включите
   приём на принимающей стороне и проверьте обмен новой тестовой задачей.

Выбирайте IP Wi-Fi, а не VPN/WSL/виртуального адаптера. При тайм-ауте проверьте
доступность обоих устройств в одной сети и разрешение входящего TCP 48766
в брандмауэре Windows для частной сети. Результат каждого шага фиксируйте
отдельно; успешная сборка APK или loopback-тест не подтверждает полевой обмен.

Проверки используют память/временные базы и подставное хранилище секретов;
пользовательский vault и системное хранилище ключей для тестов не открываются.
Проверены реальные TLS, ручное подтверждение, несовпадающий pin, отказ/повтор
приглашения, заполненная база и запись во время pairing, отзыв, restart,
остановка во время приёма и подготовки ключей, конфликты и исправление pending.
Панель проверяется widget-тестами, включая узкий экран и старые callbacks.
