# Локальный помощник OpenVINO

В основной ветке чат временно **отключён по умолчанию** (`ENABLE_ASSISTANT=false`).
Без явного включения нет кнопки/панели и загрузки OpenVINO. Эксперимент Gemma/NPU
сохранён в локальной ветке `codex/gemma-openvino-npu`; рабочий NPU-вариант пока не
подтверждён. Описание ниже относится к явно включённому модулю разработки.
MCP продолжает работать независимо: [инструкция](agent-access.md).

При явном включении модуля появляется кнопка чата справа снизу. Нажатие раскрывает панель поверх
текущего экрана. Сворачивание сохраняет сообщения и черновик; новый диалог
очищает историю. Переписка хранится только в памяти текущего запуска.
Enter отправляет сообщение, Shift+Enter добавляет строку, Escape сворачивает.
Во время ответа можно писать следующий черновик или остановить генерацию.

## Установка на Windows

Рекомендуемый стартовый профиль для Intel Core Ultra 5 125H —
[OpenVINO/Qwen2.5-1.5B-Instruct-int4-ov](https://huggingface.co/OpenVINO/Qwen2.5-1.5B-Instruct-int4-ov).
Это компактная Instruct-модель с INT4_SYM, ratio=1, group_size=128.
Симметричные веса и эта группа соответствуют рекомендациям
[OpenVINO для небольших моделей на NPU](https://docs.openvino.ai/2026/openvino-workflow-generative/inference-with-genai/inference-with-genai-on-npu.html).
Размер файла весов этой версии — около 910 МБ; отдельно нужны токенизатор,
библиотеки, Python и кэш компиляции. Маленькая модель может ошибаться, в том числе
при выборе действий; проверяйте строки «Действие» и реальные задачи.

Из PowerShell в корне проекта:

```powershell
./tool/openvino/setup.ps1 -DownloadModel
```

Установщик проверяет SHA256 официального uv, готовит изолированный Python 3.12
и OpenVINO GenAI 2026.2.1.0, скачивает IR-модель с официального репозитория
OpenVINO. Системный Python не меняется. Для своего Python 3.10–3.13 x64:

```powershell
./tool/openvino/setup.ps1 -Python 'C:\Python312\python.exe' -DownloadModel
```

Без -DownloadModel выполняется только подготовка окружения. Повторная загрузка
использует уже скачанные файлы. Скрипт печатает полные пути для настроек чата.
Потребуется драйвер Intel NPU, совместимый с OpenVINO; успешная установка Python
сама по себе не означает, что NPU доступен.

Папки .venv-openvino, .openvino-runtime и models находятся в проекте и исключены
из Git. Постоянный интерпретатор лежит в .openvino-runtime, поэтому flutter clean
не удаляет его. .venv-openvino зависит от этого интерпретатора: сохраняйте обе
папки, а после переноса проекта в другой каталог повторите установку.
Саму модель перескачивать при переносе не обязательно.

## Запуск

```powershell
C:\flutter\bin\flutter.bat run -d windows --dart-define=ENABLE_ASSISTANT=true
```

Чат включается только явно для разработки. В настройках (кнопка с ползунками в заголовке чата)
укажите Python из .venv-openvino/Scripts/python.exe и папку модели, затем выберите
NPU. Если приложение запущено из корня проекта, стандартные относительные пути
уже подходят; для готового exe укажите полные пути.

Устройство выбирается явно: NPU, GPU (первый Intel GPU) или CPU. Скрытого
переключения на другое устройство нет. Модель загружается при первом сообщении,
начальный запуск может занимать минуты из-за компиляции. Следующие запросы
используют загруженный процесс; кэш компиляции лежит в папке модели
.openvino-cache. Закрытие чата сворачивает панель, а не выгружает модель.
Остановка ответа завершает процесс; следующий запрос загружает его заново.
Смена настроек выгружает прежнюю модель и очищает контекст для новых сообщений;
прежние сообщения остаются видны в окне.

Примеры: «Покажи незавершённые задачи», «Создай задачу Купить молоко»,
«Найди задачу Купить молоко и отметь её выполненной».
«На завтра» или «на дату» означает дату начала (startsAt), без дедлайна.
Без указанного времени используется календарная дата YYYY-MM-DD: в приложении
это начало дня без заданного часа и без придуманной длительности. Дедлайн
(dueDate) задаётся только по явной просьбе — например, «дедлайн завтра».
Если нужны оба поля: «Начать завтра, дедлайн в пятницу». Помощник получает
актуальные календарные даты при каждом сообщении, включая смену месяца и года.
При неоднозначном названии помощник должен запросить уточнение.
Строки «Действие» формируются из фактических результатов API, отдельно от ответа
модели. Они показывают, что приложение действительно выполнило.

## Как это работает

Панель assistant.chat.overlay регистрирует модуль assistant.chat в app.overlays.
MainScreen не знает конкретный чат. AssistantController, контракты и нативный
адаптер находятся в agent_bridge/local_assistant.dart; Flutter-виджеты и настройки
SharedPreferences — в адаптерах приложения. ENABLE_ASSISTANT=false исключает
регистрацию чата из сборки. Веб использует заглушку процесса; для него функцию
следует выключить.

Flutter запускает приватный Python-worker через аргументы Process.start,
без shell. Worker упакован как Flutter-ресурс; при запуске он копируется во
временный каталог, который удаляется при закрытии. Передача данных — JSON lines
через stdin/stdout. Сетевого сервера для модели нет. После установки генерация
использует локальные IR-файлы; флаги HF_HUB_OFFLINE и TRANSFORMERS_OFFLINE включены.
MCP для внутреннего помощника включать не нужно.

OpenVINO выполняет инференс нативно на выбранном устройстве. Python здесь —
адаптер GenAI API, а не вычисление весов модели на интерпретаторе. При необходимости
упаковки без Python этот worker можно заменить нативным процессом, сохранив
протокол, контроллер чата и бизнес-операции.

Модель получает определения трёх инструментов через родной chat template Qwen.
Результаты передаются с ролью tool. Доступные действия совпадают с MCP:
tasks_list, tasks_create и tasks_complete; доступ к SQL, shell или файлам ей
не предоставляется. Параметры проверяются тем же TaskAgentTools. До четырёх
действий за запрос, выдача поиска ограничена десятью задачами (по умолчанию пять).
Повтор одинаковой успешной операции в одном запросе использует прежний результат.
При ошибке записи нет автоматического повтора создания.

Контекст модели — 4096 входных токенов, ответ — до 384 токенов. Сохраняются два
предыдущих запроса со всей последовательностью инструментов; старые сообщения
при необходимости убираются перед инференсом. Текущий запрос и его результаты
не обрезаются. UI показывает до ста сообщений. Настройки хранятся под ключом
assistant.openvino.v1. Инициализация приложения не загружает модель и не скачивает
файлы. Закрытие модуля запрещает новые действия, прерывает генерацию и дожидается
уже принятой записи до закрытия SQLite. На Windows останавливается всё дерево
принадлежащего модулю процесса, включая дочерний интерпретатор venv.

Голосовой ввод и синтез речи пока не реализованы.

## Проверки

```powershell
$env:ASSISTANT_TEST_PYTHON = (Resolve-Path .venv-openvino/Scripts/python.exe).Path
flutter test test/features/agents test/app/assistant_composition_test.dart --no-pub
.venv-openvino/Scripts/python.exe tool/openvino/test_worker.py
```

Проверка настоящей модели на NPU запускается отдельно и использует тестовое
хранилище в памяти, а не задачи пользователя:

```powershell
$env:LIFE_OS_TEST_OPENVINO_MODEL = (Resolve-Path models/Qwen2.5-1.5B-Instruct-int4-ov).Path
dart test test/features/agents/openvino_model_test.dart
```

Без этих переменных аппаратная проверка пропускается. Обычный CI проверяет
протокол Python без OpenVINO/модели и тестовый процесс без NPU. Статус общей
проверки проекта записан в AGENTS.md.
