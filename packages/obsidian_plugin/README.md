# Интеграция Obsidian

`ObsidianPlugin` подключает выбранный vault, отслеживает его настройку и владеет
жизненным циклом файлового движка. `ObsidianVault` сканирует `.md`, следит за
изменениями каталогов, читает/сохраняет/создаёт заметки и предоставляет файловые
возможности Canvas, экспорта, папок, копий и переименования через `notes_api`.

- [Все функции графа и заметок, пользовательские действия и API](../../docs/lifegraph-plugin.md).
- [Полное описание файловой интеграции, формата, конфликтов и ограничений](../../docs/obsidian-canvas.md).
- [Архитектурные границы и жизненный цикл](../../docs/modular-architecture.md).

Настройки Boards/Notes/Exports/Backups принадлежат модулю графа; интеграция
Obsidian управляет только vault. Движок переиспользуется адаптером `graph.storage`
как библиотека для локального корня Pulse при `ENABLE_OBSIDIAN=false`.
Бизнес-иерархия не импортируется из Obsidian в БД, плагины Obsidian не запускаются.

## Функции файлового движка

| API | Назначение |
| --- | --- |
| `openVault`, `state`, `watch`, `refresh` | Выбор корня, рекурсивное сканирование .md, состояние и события; скрытые файлы/папки пропускаются |
| `graphMarkdownState`, `obsidianState` | Раздельные представления папки новых заметок и всего источника |
| `readContent`, `writeContent`, `createNote` | Чтение, запись через временный файл и эксклюзивное создание заметки |
| `folders`, `configureFolders`, `listFolders` | Нормализация каталогов, настройка Boards/Notes/экспортов/копий и список доступных папок |
| `canvasNotePath`, `createCanvas` | Относительный путь заметки и новый файл экспорта |
| `openCanvasBoard` | Сессия основной доски с защитой от смены корня |
| `CanvasBoardSession.read/write` | Чтение и запись с проверкой ожидаемого содержимого; резервные/конфликтные снимки |
| `CanvasBoardSession.notePath/resolveNote` | Преобразование путей между Canvas и файловой системой |
| `saveMarkdownCopy` | Новая копия текста в выбранной абсолютной папке без перезаписи |
| `renameMarkdownNote` | Переименование .md в прежней папке и обновление основных досок |
| `deleteMarkdownNote` | Удаление .md из текущей Notes с проверкой пути/поколения; карточки Canvas остаются |
| `remapNoteReferences`, `resolveNotePath`, `watchNoteRenames` | Обновление ссылок другого текущего корня и разрешение прежних путей/события |
| `flush`, `stop`, `dispose` | Завершение очереди, остановка watcher-ов и окончательное освобождение потоков |

Файловые операции сериализованы; изменения источника публикуются через VaultState.
Наблюдение обновляет каталог Markdown. Непрерывной синхронизации открытого Canvas
с внешним редактором нет. Формат и подробные правила восстановления — в документации
по ссылкам выше. Параметр watchDirectory позволяет подставить наблюдение в тестах.
